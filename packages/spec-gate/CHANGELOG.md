## [Unreleased]

### Added

- Initial package scaffold: CLI with --help and --version.
- Format schemas and pure parsers for `spec.md`, `testplan.yaml`, `bindings.yaml`, `triage.json`, `questions.json`, `.spec-gate/config.yaml`, `.spec-gate/commands.yaml` and evidence envelopes, with the field-to-layer table, the per-kind required fields, ID and source-line ID handling, the reference-state table and the evidence phase rules, documented in `docs/formats.md`.
- `spec-gate digest <spec-dir> [--repo <path>]`: a deterministic `sha256:` digest of the normative layer of a spec, frontmatter `id` included (canonical JSON per RFC 8785, whitespace normalised in prose fields only, `commands_ref` a full commit ID and the referenced argv lists read from git at that commit, from a regular file at the repository root only; `input`, `steps`, `environment` and `verifier` are kept exactly), with golden fixtures and the rules in `docs/digest.md`.
- `triage` verb: derives the triage class from `triage.json` with a versioned truth table in `src/triage/`, writes `class` and `rule_version` back through a temporary file renamed into place, keeping the file's permission bits and never removing a path it did not create (a symlink, or a file or directory that cannot be written, is refused with a named error), and reports the class, the deciding row, every unknown field of the precedence rows when an unknown forces `clarify`, and the spec profile; the rule is documented in `docs/triage.md`.
- `intake file` CLI verb: create `specs/<id>/source/` in the target repository from a local file with `base_commit` and `commands_ref` read from the remote default branch, a secret scan before anything is written, optional attachments and `--no-raw`, and a `--check` drift mode.
- `spec-gate lint <spec-dir> [--strict] [--final] [--profile <light|full>] [--config <path>]` and `lint-ack`: a deterministic JSON report (`spec-gate-lint/1`, findings sorted, nothing machine-local) over a rule registry with profiles and status gating, a git-free loader that refuses links, non-regular files, files over 4 MiB and non-UTF-8 text and turns every format error into a finding, the profile taken from `triage.json` (in-memory derivation, `--profile` only as a fallback), `acks.yaml` for acknowledged warnings with an atomic append writer, a `skipped` list naming the rules a run did not evaluate and why, and the form rules for one GOAL, AC coverage by a test-plan row and non-empty Non-goals; documented in `docs/lint.md`. Fifteen content rules run in the full profile: DF coverage, covers and binding references, source-ledger completeness and references, `owner: none`, open residuals and blocking questions gated on `proposed`, DC answers and checkable provenance, retired IDs still in use, vague words in normative text, an unanswered-question budget settable through `--config` (config findings name `config:<basename>`, never the caller's path), and the freshness of `triage.json`, checked in both profiles, whose stored class never picks the profile. Reference states are checked against git with `--repo`, `--default-ref` and `--base` (offline, read-only, a scrubbed git environment, regular files only at a commit): `base_commit` and `commands_ref` must equal their `source/meta.json` copies and be ancestors of the reference commit, a spec change under `.spec-gate/` is an error, every `static` row must name a command of the set at `commands_ref`, `.spec-gate/config.yaml` is read at the reference commit, and under `--final` an error rule skipped for no git or an absent input is itself an error (`rule-skipped`). The repository is the one `--repo` names (required with `--default-ref` or `--base`, never discovered from the spec directory), `--base` must lie on the `--default-ref` branch when both are given, and a spec change under `.spec-gate/` is matched without regard to the case of its first path component.
- `spec-gate propose` and `spec-gate bind` with `bindings.log`: `propose` needs git inputs, a `draft` status, no existing log and a work tree whose `spec.md` and `bindings.yaml` are the files at `HEAD`, runs the final lint in process (findings exit 1 and write nothing), then sets `status: proposed` alone (the digest stays the same) and records the propose commit and the hash of the committed `bindings.yaml`; `bind` changes one existing binding of a proposed spec within the rule of its row's kind, appending the full binding to a hash-chained log and rewriting `bindings.yaml`. The new lint rule `bindings-log` (gated, needs git) checks the log's sequence, shape and chain, that the propose commit is an ancestor of `HEAD`, the hash of `bindings.yaml` read from git at that commit, that no bind entry adds an ID, that the replay equals `bindings.yaml`, and that a log at the diff base is never rewritten or removed. Exit codes follow `lint` and `lint-ack` (0 written, 1 findings, 2 refusal); the log format is documented in `docs/formats.md`, the verbs and the rule in `docs/lint.md`.

### Security

- `intake file` hardening: the remote default branch is validated and fetched by its full `refs/heads/` name only (a tag of the same name, or a branch named like a git option, can no longer change `base_commit` or the local repository), git runs with a scrubbed environment in its own process group, `--remote` must be a configured remote and no error echoes a URL, the secret scan covers keywords inside identifiers, quoted keys, PGP key blocks and `ghr_` tokens and refuses UTF-16 and NUL input, writes are atomic and rolled back, and `--check` exits 2 on an error.
- `intake file` exits 2 on its own usage errors and unexpected exceptions (exit 1 belongs to `--check` drift alone), refuses a `specs` or `specs/<id>` that is already a symlink with `source-not-in-repo` before anything is written, and the fetch passes `--write-fetch-head` so a repo-local `fetch.writeFetchHEAD=false` cannot leave a stale FETCH_HEAD; the remote is trusted as configured (local-path URLs and `url.<base>.insteadOf` rewrites included), with integrity against the shared upstream deferred to lint.
- Every git call of `lint`, `digest` and `intake` is started with `safe.bareRepository=explicit`, `core.fsmonitor=false`, `core.hooksPath` set to the null device and (not for `intake`, which fetches) `protocol.allow=never`, with `GIT_GRAFT_FILE` set to the null device and (not for `intake`) `GIT_ALLOW_PROTOCOL` set to the empty string, so that no transport starts whatever the repository's `protocol.<name>.allow` says (these protections need git 2.38 or newer), and a git that is stopped by a signal is a `git-failed` error instead of a refusal; `digest` and `lint` use a repository only when the `.git` entry of its work tree (a directory or a `gitdir:` file, never a symbolic link) leads to the git directory git found and the common git directory is not inside the work tree, so a spec pull request cannot commit a git directory of its own while a linked worktree, also one inside a bare repository, is accepted, and `digest --repo` no longer accepts a bare repository or a git directory.
